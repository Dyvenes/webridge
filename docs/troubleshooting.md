# Диагностика

## Быстрая проверка

```powershell
webbridge serve
curl http://127.0.0.1:8000/healthz
```

`/healthz` не требует токена и показывает список загруженных сервисов.
Если сервиса нет в списке — он выключен в конфиге или не создался адаптер.

```powershell
$env:TOKEN = webbridge token
curl -H "Authorization: Bearer $env:TOKEN" http://127.0.0.1:8000/v1/models
```

## opencode не подключается

| Симптом | Что проверить |
|---|---|
| `401 authentication_error` | Токен в `~/.webbridge/api_token` не совпадает. Выполните `webbridge token` и перезапустите opencode. |
| `404 model_not_found` | Алиас модели отсутствует в `services.*.models`. Сверьте `/v1/models`. |
| `connection refused` | Мост не запущен или слушает другой порт. |
| `Host` отклонён | Обращайтесь на `127.0.0.1` или `localhost`, не на внешний IP. |
| Провайдер не виден | Проверьте `opencode.json`: `providers.webbridge`, `package`, `baseURL`. |

## `401` / `NeedsLogin`

Веб-сессия истекла. Выполните:

```powershell
webbridge login deepseek
```

Профиль браузера сохраняется, поэтому повторный вход обычно быстрый.

## `403 captcha_required`

Сервис просит капчу. Откройте браузер с профилем вручную, пройдите проверку и
повторите запрос. Не пытайтесь обходить капчу автоматически.

## `429 rate_limited`

Сработал бюджет моста (`limits.max_requests_per_hour/day`) или ограничение сайта.
Ответ содержит `Retry-After`. Увеличьте лимиты в конфиге или подождите.

## `409 session_busy`

В одну сессию одновременно пришло два запроса. opencode обычно повторяет запрос;
если нет — дождитесь завершения текущего хода. Разные сессии opencode получают
разные вкладки и не блокируют друг друга.

## `409 request_conflict`

Повторный запрос с тем же `request_hash`, но предыдущий ход не завершён. Мост не
отправляет его повторно, чтобы не дублировать сообщение в веб-чате. Дождитесь
завершения или сбросьте сессию:

```powershell
curl -X POST -H "Authorization: Bearer $env:TOKEN" `
  http://127.0.0.1:8000/admin/sessions/<session_id>/reset
```

## `502 bad_model_output`

Модель ответила, но не в формате tool-протокола: нет блока ```` ```tool ````,
неизвестный инструмент, аргументы не проходят JSON Schema. Проверьте:

- в запросе действительно были `tools`;
- системный промпт не переопределён клиентом;
- модель не пытается вызвать инструмент, которого нет в списке.

Повторите запрос. При систематических ошибках упростите схемы инструментов или
смените модель.

## `504 timeout`

Генерация не завершилась за `limits.max_generation_s`. Увеличьте лимит или
проверьте, не зависла ли вкладка. `Turn.aclose` нажимает «Стоп» при обрыве
соединения, но зависшая страница может требовать перезапуска `serve`.

## `SelectorBroken`

Сайт изменил разметку. Мост пишет, какой элемент не найден. Обновите
`~/.webbridge/selectors/<service>.yaml`; встроенные селекторы лежат в
`src/webbridge/adapters/selectors/`. Не делайте селекторы слишком широкими:
`text=/limit/` может поймать слово «limit» в ответе модели.

## Браузер не запускается

```powershell
playwright install chromium
```

Если используется `channel: chrome`, убедитесь, что Chrome установлен. Для
отладки оставьте `browser.headless: false` — так видно, что происходит на
странице.

## Долгие ответы и «зависшая» вкладка

- Проверьте, не открыт ли диалог вручную в том же профиле.
- Закройте лишние вкладки: `SessionManager` закрывает простаивающие, но не
  трогает активные.
- Перезапустите `webbridge serve`; состояние сессий в SQLite сохранится.

## Логи и метрики

- Логи — в `~/.webbridge/logs/`, структурированный JSON.
- `/metrics` — Prometheus-текст: запросы, ошибки, активные запросы, длительность.
- Секреты в логах редактируются, но не передавайте логи публично без проверки.

## Полный сброс

```powershell
# Остановите serve, затем:
Remove-Item -Recurse -Force ~/.webbridge/profiles
Remove-Item ~/.webbridge/state.sqlite3
webbridge login deepseek
```

Это удалит браузерные профили и историю сессий. Конфиг и токен сохранятся.
