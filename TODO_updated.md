## 0. Правила для исполнителя (нейросети)

Читай этот раздел перед каждым пунктом.

### 0.1 Как работать с файлом

1. Бери **один** пункт за раз, в порядке фаз и зависимостей (`Зависит от`).
2. Перед правкой кода прочитай сам код модуля. Не доверяй `PROJECT_MAP.md` вслепую: он сгенерирован автоматически и местами неточен.
3. Закончив, поставь `[x]`, допиши строку в `CHANGELOG.md` и, если менялось поведение или контракт, обнови `docs/`.
4. Пункт считается выполненным только если выполнено условие **«Готово, когда»** и прошла **«Проверка»**.
5. Если пункт зависит от нерешённого вопроса `[Qn]` (см. раздел 2), используй значение **по умолчанию** из таблицы и запиши допущение в `CHANGELOG.md`.
6. Если пункт неоднозначен или противоречит коду, остановись и задай один конкретный вопрос, а не угадывай.

### 0.2 Жёсткие правила

- **Тесты никогда не обращаются к реальным сайтам и аккаунтам.** Только `tests/fake_site`, фикстуры и фейковые адаптеры. Живые проверки только под маркером `@pytest.mark.live` и только по явной просьбе человека.
- **Не обходить защиту сервисов.** Капча, челлендж, предупреждение об аномальной активности → остановка и сигнал человеку (`CaptchaRequired`/`NeedsLogin`), а не обход. Не добавлять решатели капчи и агрессивную подмену отпечатков.
- **Секреты:** куки, профили браузера, токен API, содержимое `.env` и ключи не попадают в логи, артефакты, фикстуры, коммиты и ответы API. Любая новая точка вывода проходит через редактирование секретов.
- **Не менять публичный контракт** (`/v1/chat/completions`, `/v1/models`, формат ошибок, заголовки) без записи в `docs/adr/` и обновления контрактных тестов.
- **WebBridge не исполняет инструменты.** Файлы, bash и права доступа обрабатывает opencode. Не добавлять выполнение команд в мост.
- Код: Python 3.11+, async/await, type hints, `pathlib`, UTF-8 везде, нормализация `\r\n` при разборе текста сайтов. Платформа основной разработки: **Windows** (пути, кодировки, `asyncio` + Playwright, права на файлы).
- Один пункт = одна отдельная задача реализации. Исполнитель в веб-чате не имеет доступа к локальному репозиторию, Git, PowerShell и Playwright: не заявлять, что файлы изменены или тесты запущены.
- Пользователь самостоятельно вносит изменения, запускает локальные проверки и управляет Git. Исполнитель выдаёт либо полный текст файла, либо точные фрагменты с подробным указанием, что и где заменить.
- Не требовать от пользователя передавать много файлов сразу: запрашивать только минимально необходимые файлы и их содержимое.
- Каждая новая функция с логикой получает тест. Каждый исправленный баг получает регрессионный тест.
- Не добавлять зависимости без причины; если добавляешь, укажи зачем в `CHANGELOG.md` и закрепи версию.

### 0.3 Определение «готово» для любого пункта

- [ ] Тесты пункта написаны и проходят: `uv run pytest -q`
- [ ] Весь набор тестов проходит, количество пропущенных не выросло
- [ ] `uv run ruff check .` и `uv run ruff format --check .` чистые (после P0.3)
- [ ] Типы: `uv run mypy src` без новых ошибок (после P0.3)
- [ ] Документация и `CHANGELOG.md` обновлены
- [ ] Нет секретов и отладочного мусора в диффе

### 0.4 Команды (Windows, PowerShell)

```powershell
uv sync
uv run pytest -q
uv run pytest -q -m "not live"
uv run ruff check . ; uv run ruff format --check .
uv run mypy src
uv run webbridge serve
uv run webbridge login deepseek
```

> Примечание по процессу: команды выше выполняет пользователь в локальном PowerShell. Веб-исполнитель не может запускать их в репозитории пользователя, проверять реальное состояние Git или выполнять живые проверки.

## 2. Решения, от которых зависит план

Формулировки вопросов — в чате. Здесь для каждого указано значение **по умолчанию**; если человек не ответил, действуй по нему. Человек может заменить значение в колонке «Решение».

| # | Тема | По умолчанию | Решение пользователя |
|---|---|---|---|
| Q1 | Нагрузка | Кодинг в одном репозитории, 1–2 параллельные сессии opencode, есть субагенты (`task`) | Один основной проект/репозиторий; одновременно одна основная сессия; длительные задачи и субагенты нужны |
| Q2 | Критерий успеха | Задача из 20+ шагов без ручных правок; ≥90 % tool-вызовов без повтора | Задача из 20+ шагов без ручных правок; не менее 90 % tool-вызовов успешны с первой попытки |
| Q3 | Приоритет | Надёжность > безопасность > скорость > новые сервисы | Надёжность — главный приоритет |
| Q4 | Сервисы сейчас | DeepSeek и Claude; новые — после стабилизации | Только DeepSeek и Claude на текущем этапе |
| Q5 | Несколько аккаунтов | Нет | Да: несколько отдельных профилей/аккаунтов одного сервиса; возможность переключения при недоступности основного — только в рамках правил соответствующего сервиса, без обхода капчи/антибот-защиты и запрещённых ограничений |
| Q6 | Фолбэк между сервисами | Выключен; только внутри сервиса | Разрешён; при переключении переносить контекст текущей сессии |

| Q8 | Браузер | Headed, на том же Windows-хосте | Сейчас headed для отладки; после стабилизации пользователь самостоятельно переключит режим на headless |

| Q13 | Формат tool-вызовов | XML, один вызов на ответ; параллельные выключены | XML оставить; параллельные tool-вызовы поддерживать; отдельный повтор запроса допустим |
